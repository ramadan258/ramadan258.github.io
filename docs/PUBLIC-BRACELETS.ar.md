# الأساور العامة التلقائية

## قرار الإصدار الحالي

أُجّل تفعيل الأساور العامة إلى تحديث مستقل بقرار صاحب الموقع. بقي العرض العام معطّلًا، وأُغلق تنفيذ مهمة GitHub بشرط ثابت `false` حتى لو تغيّر متغير المستودع بالخطأ.
يستمر السوار الشخصي من بيانات صاحبه فقط. لا يتطلب إطلاق تحسينات الأداء والجلسات والتوقيت المحلي أي إعداد WIF أو IAM جديد.
تفاصيل الناشر أدناه تجهيز مؤجل، وليست شرطًا لإطلاق الإصدار الحالي أو ادعاءً بأنه يعمل في الإنتاج.

## القرار والتنفيذ المحلي

مهمة GitHub Actions كل ساعة عند الدقيقة 17، لا تحتاج لابتوبًا أو تشغيل أمر يومي.
تقرأ بيانات Firestore المحفوظة بصلاحية قراءة فقط، وتعيد استخدام `deriveBracelet` الموجود.
تنشر `current.json` وحده على فرع مستقل اسمه `bracelet-data`، وليس `main` أو ملفات الموقع.
المتصفح يقرأ الملف العام دون Firebase أو رمز حساب، مرة واحدة للقائمة ثم كل خمس دقائق أثناء ظهور الصفحة.
لا يوجد تغيير مطلوب في قواعد Firestore، ولا كتابة من الناشر إلى Firebase.

حساب أمس بحسب آخر منطقة زمنية حفظها العضو على جهازه. أول يوم مؤهل هو 17 أكتوبر 2026 من إنجازات 16 أكتوبر.
تُحفظ المنطقة الزمنية داخل catalog الخاص عند فتح المزايا الشخصية، ثم عند تغيرها فقط؛ لا تُغيّر مفاتيح الأيام القديمة.
عند استخدام أجهزة بمناطق مختلفة، تُعتمد آخر منطقة حُفظت بنجاح؛ لا يمكن معرفة سفر عضو غير متصل.
العضو الذي لم يحفظ منطقة زمنية صحيحة يبقى محايدًا، دون افتراض توقيت موحد.
تُحترم نسخ جداول العادات التاريخية، وتبقى «لا» و«دون إجابة» منفصلتين في البيانات.

المخرجات العامة محصورة في: إصدار البنية، وقت إنتاج الملف وصلاحيته، ومعرّف العضوية ولونها.
لا تتضمن UID أو التوقيت الشخصي أو أسماء العادات أو عددها أو النسب أو التقارير.
الألوان المنشورة عامة، وتبقى نسخها السابقة في تاريخ فرع Git؛ لا يُرفع إليه أي سجل خاص حتى في الإصدارات القديمة.
السجل اليومي مخزّن أصلًا كـJSON واحد؛ لذلك تقرؤه المهمة الموثوقة في الذاكرة، ثم تستبعد التقرير ولا تطبعه أو تحفظه أو ترفعه.
تراجع المهمة ارتباط العضوية الجديد في الطرفين وحالة الدليل والملف؛ لا تقرأ روابط bindings القديمة.
لا يُقبل لون يرسله العضو: اللون محسوب من عاداته وحالات إنجازه المخزنة. الإنجازات نفسها تظل إبلاغًا ذاتيًا، وليست إثباتًا خارجيًا للسلوك.
الضيف يبقى محليًا تمامًا، ولا تدخل بياناته في هذه المهمة.

## حدود التحديث

مهمة GitHub دورية وليست خدمة لحظية؛ قد تتأخر أو تفوت دورة. لا نضمن النشر عند منتصف الليل تمامًا.
تعديل إنجاز قديم يظهر في الدورة التالية، ثم لدى المشاهد خلال دورة جلب الملف؛ ليس فور الضغط.
صلاحية الملف أقصاها 65 دقيقة، أو أقرب منتصف ليل محلي لأي عضوية ذات توقيت معروف، أيهما أسبق.
بعدها يظهر المحايد للجميع حتى وصول ملف جديد، بدل عرض لون محسوب ليوم منتهٍ.
هذا قد يسبب فترة محايدة مؤقتة، ولا يعني ضعف التزام العضو.
لا توجد قراءة لعادات الآخرين من متصفحات الأعضاء. صاحب العضوية والمشاهدون يستخدمون الملف نفسه عند تفعيل العرض العام.

GitHub قد يعطّل الجدولة في المستودعات العامة بعد 60 يومًا من عدم النشاط؛ تُراجع إشعارات فشل المهمة وحالتها، لا يلزم تشغيل اللابتوب يوميًا.
لا ينشأ ترتيب تنافسي. إشعار الواجهة الموجود يوضح أن اللون عام وتبقى التفاصيل خاصة.

## خطوة التفعيل التي تحتاج موافقة

لم تُنشأ موارد IAM أو WIF، ولم تُقرأ بيانات أعضاء إنتاجية ولم يُغيَّر أي إعداد أو قاعدة.
بقي `publicBracelets: false` و`publicBraceletsDeferred: true` عمدًا، والمهمة لا تعمل على فرع PR.
لا يكفي تغيير هذين الخيارين قبل تجهيز جهة النشر والتحقق منها.

الخطة بعد موافقة منفصلة:

1. التحقق أولًا من إمكانية إعداد Workload Identity Federation على المشروع الحالي دون ربط حساب فوترة. إن طلب Google فوترة نتوقف ولا نفعّل Blaze.
2. إنشاء حساب خدمة مستقل `wa3i-bracelets-publisher` دون مفاتيح. لا يُستخدم حساب أداة إدارة العضويات.
3. فحص الصلاحيات الفعلية والموروثة قبل منح دور مخصص لا يتضمن إلا `datastore.entities.get` و`datastore.entities.list`. هذه قراءة على نطاق قاعدة المشروع وليست عزل IAM لمسارات أفراد؛ لا تمنح أي إنشاء أو تعديل أو حذف أو إدارة Authentication.
4. ربط إصدار الرمز القصير بواسطة `roles/iam.workloadIdentityUser` على حساب الخدمة هذا فقط. تقييد مزود GitHub بالهوية الرقمية للمستودع والمالك والفرع وملف المهمة والحدث، وليس باسم قابل لإعادة الاستخدام وحده.
5. استخدام شرط الثقة التالي، بعد مراجعة أذونات الدور الفعلية: `assertion.repository_id == '1210383914' && assertion.repository_owner_id == '179522853' && assertion.ref == 'refs/heads/main' && assertion.workflow_ref == 'ramadan258/ramadan258.github.io/.github/workflows/public-bracelets.yml@refs/heads/main' && assertion.event_name in ['schedule', 'workflow_dispatch']`.
6. التحقق من إصدار رمز قراءة لمدة 600 ثانية ومن رفض الكتابة بفحص الأذونات دون إنشاء مستند اختبار إنتاجي. رمز GitHub يملك `contents:write` للمستودع أثناء المهمة، وليس صلاحية سحابية معزولة لفرع واحد؛ حواجز الكود تثبت مسار الفرع، ويوصى بحماية `main` من كتابة التطبيقات مباشرة.
7. بعد الموافقة على دمج PR وضبط متغير `BRACELETS_WIF_PROVIDER`، تفعيل `PUBLIC_BRACELETS_ENABLED=true`، وإنتاج ملف عام أول ومراجعة شكله. ثم تفعيل خياري العرض في حزمة الموقع بإذن نشر منفصل، والتحقق من نفس اللون من حسابين.

المصادقة دون مفاتيح تمنع سرًا دائمًا داخل GitHub، لكنها تتيح للمهمة الموثوقة قراءة البيانات الخاصة في الذاكرة. يجب مراجعة تغييرات ملف المهمة والناشر قبل دمجها، وألا تُنفّذ من PR أو fork.
لا توجد اختبارات إنتاجية أو موافقة ضمنية على قراءات هذه المهمة في هذا التغيير.

## التكلفة والقيد غير المحسوم

المستودع عام، وتشغيل GitHub القياسي مجاني. لا تستخدم الخطة Cloud Functions أو خدمة تتطلب Blaze.
الناشر يحد قراءة الدليل إلى 100 سجل نشط، بالإضافة إلى المعالجة الخاصة لحساب الأدمن، وبحد أقصى تقريبي 16,848 قراءة مستند يوميًا عند 24 دورة كاملة، مع ترك بقية حصة Spark للموقع.
العدد الفعلي قد يقل عند غياب بيانات مؤهلة. طلبات الدفعات لا تلغي احتساب كل مستند، والسجلات المفقودة لها تكلفة قراءة.
إذا تجاوز الدليل 100 عضوية تتوقف المهمة بدل استبعاد أعضاء بصمت؛ يلزم وقتها مراجعة الحصة والجدولة. خطأ التشغيل لا يزيد الطلبات بإعادات محاولة غير محدودة.

IAM يعلن أن WIF مجاني، لكن دليل Google لإعداد الاتحاد يذكر تفعيل الفوترة ضمن المتطلبات. مجانية الخدمة لا تثبت قبول الإعداد على مشروع Spark غير مرتبط بفوترة.
لم يُختبر هذا الإعداد في الإنتاج لأن الموافقة الحالية تمنع ذلك. لهذا لا يمكن ضمان التشغيل يوم 17 أكتوبر قبل اجتياز بوابة التحقق هذه.
إذا اشترط Google حساب فوترة، فهذا مانع محدد للخطة، ولا نعالجه بمفتاح دائم أو صلاحية أوسع أو كشف البيانات. يبقى العرض العام محايدًا لحين اعتماد بديل استضافة موثوق مجاني، ولا يُدّعى اكتمال الميزة.

## التحقق المحلي لهذه الإضافة

نجح 14 اختبارًا مخصصًا للناشر والقراءة العامة: الحدود الرياضية، منتصف الليل المحلي والتوقيت الشتوي، المصدر التاريخي المشترك، عدم نشر تفاصيل خاصة، استبعاد الروابط القديمة، اتساق لقطة الخادم، انتهاء الصلاحية، قلة الطلبات، وحواجز المهمة والفرع.
نجح فحص منفصل في مشروع وهمي داخل محاكي Firestore القائم: حفظ التوقيت الخاص والإنجاز، منع قراءة بيانات عضو آخر أو ضيف، ورفض كتابة لون عام مزور أو تقييم يدوي. نجحت قراءة REST المتسقة وإعادة حساب اللون من السجل المحفوظ.
نُظف مشروع المحاكي الوهمي وحده. لم تُعد اختبارات الأداء، ولم تُعد تشغيل المعاينة أو تمس بياناتها.
هذه النتائج لا تثبت إعداد WIF أو IAM الفعلي أو تشغيل جدول GitHub في الإنتاج؛ تلك خطوة التفعيل المنفصلة المذكورة أعلاه.

## التراجع الآمن

تعطيل `PUBLIC_BRACELETS_ENABLED` يوقف المهام القادمة، وإلغاء ربط WIF يمنع إصدار رموز جديدة؛ تنتهي الرموز القائمة خلال عشر دقائق.
الملف السابق يصبح محايدًا تلقائيًا عند انتهاء صلاحيته، ويمكن إعادة تعطيل العرض العام بإذن نشر.
لا نعيد قواعد ضعيفة، ولا نغيّر بيانات العضويات أو تقاريرها أو صلاحيات أمجد.

# مراجعة الجلسات والأداء وبداية التتبع

## الحالة والنطاق

- الفرع: `codex/session-performance-oct16`، انطلاقًا من `0159a375301309cd1948d7dfbd47953ce2e7f2ca`.
- بداية التتبع: الجمعة **16 أكتوبر 2026**، والمنطقة الزمنية `Europe/Stockholm`.
- هذه نسخة مراجعة فقط. لم يتغير Firebase الإنتاجي أو IAM أو Authentication أو بيانات الأعضاء، ولم يُرفع `main` أو يُدمج طلب مراجعة.
- GitHub Pages مضبوط على `main` ومسار `/`. مسار CI الحالي يتحقق من القواعد والاختبارات والبناء فقط، ولا ينشر الفرع.

## ما اكتمل

- تظهر الرئيسية العامة مباشرة؛ اختيار المستخدم اختياري، والضيف افتراضي عند عدم وجود هوية Firebase صالحة. يظهر اسم العضو دون صورة في رأس الصفحة.
- Auth مهيأ مرة واحدة لكل وثيقة مع استعادة مستمرة بين الصفحات. تظل صلاحية العضو مبنية على هوية Firebase والربط الموثوق من الخادم، لا تلميح المتصفح.
- الأخطاء المؤقتة تقفل العرض والكتابة الخاصين وتحافظ على هوية Auth لإعادة المحاولة؛ الإبطال المؤكد ينهي الوصول. فتح قائمة اختيار المستخدم لا يسجل الخروج؛ التبديل الفعلي ينتظر حفظ المسودات.
- تجميع قراءات التحقق المتزامنة في طلب REST واحد عند توفر تلميح العضوية، أو طلبين عند غيابه. يستخدم الطلب Firebase ID token وتطبق عليه قواعد Firestore نفسها. لا يختزل ذلك تلقائيًا عدد القراءات المفوترة: مستمعات الإبطال الحية تبقى فعالة.
- إزالة استطلاع التهيئة كل 80 مللي ثانية، وتأجيل مستمعات سؤال وجواب والمكتبة إلى الفتح، وتأجيل قراءة دليل صلاحيات الأدمن إلى فتح إدارة الأعضاء.
- تحميل كتالوج العادات واليوم المطلوب أولًا؛ تحميل الفترات التاريخية عند الحاجة وإعادة استخدام نطاقاتها. لا تحميل لأرشيف التقارير الخاصة من الرئيسية.
- إزالة الأولويات والمهام وربط الهدف والمحرر غير المستخدم. بقيت العادات وتاريخ جداولها وحصادي والتقرير المتتابع.
- مصدر واحد لحالات العادات في التقرير وخُطاي. «نعم» و«لا» و«دون إجابة» مستقلة. التعارض السحابي يوقف الكتابة ويحفظ مسودة الطرف الخاسر بدل الكتابة الصامتة فوق سجل أحدث. أوامر الضيف متسلسلة بين التبويبات.
- تخزين الضيف مستقل عن الأعضاء والتقارير القديمة، دون إنشاء حساب ضيف أو نقل بياناته للسحابة. الحفظ السحابي للأعضاء باقٍ.
- بصمة إصدار وروابط متناسقة تمنع مزج صفحات مخبأة من إصدار قديم مع الملفات الجديدة. البناء قابل للتكرار؛ حزم الإصدارات المتتبعة القديمة محفوظة لسلامة الذاكرة المخبأة.

## تاريخ الانطلاق والبيانات

تستخدم بيانات التتبع الجديدة علامة `trackingPeriod: 2026-10-16` ومساحة محلية جديدة للضيف ومسودات الأعضاء. الكتالوج السابق يعامل ككتالوج فارغ، وسجلات الفترة السابقة لا تدخل الإحصائيات. لا يوجد حذف جماعي أو استيراد تلقائي، ولا تغيير في UID أو كلمات المرور أو الصلاحيات. عند أول تعديل جديد يستبدل كتالوج التتبع القديم باستخدام فحص المراجعة المتزامنة نفسه؛ التقارير القديمة لا تُنسب إلى مستخدم آخر.

يمكن تجهيز العادات قبل 16 أكتوبر لتسري ابتداء منه، لكن إنجازات الأيام المستقبلية والتقارير المستقبلية ممنوعة. اختُبر 16 و17 و18 أكتوبر وحد منتصف الليل والتوقيت الشتوي في ستوكهولم. معاينة المحاكي تحاكي يوم 16 أكتوبر فقط؛ هذا الاستثناء محصور بعنوان loopback ومشروع `demo-`، ولا يغير ساعة Authentication أو التاريخ الحقيقي في الإنتاج.

## القياسات الفعلية

البيئة: متصفح الكمبيوتر المحلي، Auth وFirestore Emulator، تأخير مصطنع **180 مللي ثانية لكل طلب**، وبقاء ذاكرة الموارد المتاحة أثناء التنقل. ليست محاكاة عرض نطاق/معالج هاتف ضعيف، ولا قياسات من هاتف أو Firebase الإنتاجي. القيم عينات وليست متوسطات إحصائية.

## نتائج التحقق

- نجح `npm test`: **25 اختبارًا**، منها حواجز سلامة القواعد، استعادة الجلسة، التمييز بين الاتصال والإبطال، إعادة المحاولة، قفل الكتابة، الوقت، الجداول التاريخية، التخزين المحلي والتزامن بين محرري ضيف.
- نجح سيناريو التكامل في Firebase Emulator الحقيقي: دخول أدمن وعضوين وهميين، bootstrap، تجاهل بيانات الفترة القديمة دون حذفها، الحفظ والخروج والعودة والاسترجاع، بقاء دون إجابة، منع قراءة عضو آخر، رفض روابط الانتحال، رفض الإبطال، واكتشاف تعارض محررين دون فقد المسودة.
- نجح فحص الواجهة: الضيف ثم عضو أول ثم عضو ثان ثم أدمن وهمي ثم ضيف، بلا اختلاط بيانات؛ تحديث الصفحة والتنقل بين الرئيسية والتقرير وخُطاي دون خروج غير مقصود؛ ظهور الإعدادات وإدارة الأعضاء للأدمن؛ إنشاء العادة وتعديلها وحذفها؛ المزامنة في الاتجاهين واسترجاع الإجابة بعد الحفظ والتحديث؛ حصادي يبدأ 16 أكتوبر والأيام المستقبلية لا تدخل المقام.
- نجح فحص 320 و390 بكسل عبر إطارات متصفح فعلية بهذه الأبعاد؛ قياسات عرض المستند وscrollWidth متطابقة دون تجاوز أفقي. الصور محفوظة محليًا في `.review/` وغير مرفوعة إلى Git.
- `npm audit`: لا ثغرات معروفة في الاعتماديات المثبتة. لم تظهر أخطاء JavaScript عند إعادة فحص الرئيسية وخُطاي في تبويب نظيف. ظهر خطأ `MutationObserver` مرتين أثناء فحص الإطارات؛ أضيف حارس لرصد القياس المحلي عند زوال عقدة الصفحة، دون تغيير واجهة الإنتاج.
- ملف `firestore.rules` لم يتغير؛ بصمته المعتمدة `f41fd8338988c42fdfdba341da6b26ee487d710776a68ab136e233f403ab6a5c`. UID أمجد والإعدادات الإنتاجية لم تتغير. الأساور العامة محايدة.

## الحدود والخطوة التالية

لم يُختبر هاتف حقيقي أو معالج ضعيف أو انقطاع شبكة فعلي في الهاتف، ولم يُستخدم حساب أمجد الحقيقي أو حساب عضو حقيقي في هذا الفرع. انقطاع الاتصال وعودته والإبطال اختُبرا بمحاكاة runtime وقواعد المحاكي. إغلاق تطبيق المتصفح بالكامل ثم فتحه لم يُختبر؛ استمر الحفظ بعد تحديث الصفحات وإعادة إنشاء مخازن الاختبار.

المطلوب بعد مراجعة PR: تجربة الهاتف الفعلية والموافقة على الدمج والنشر. لا يعد هذا التقرير تأكيدًا لحل مشكلة أداء الإنتاج بالكامل.

المعاينة المحلية: `http://127.0.0.1:5390/`، وعرض الهاتف: `/responsive-390.html` أو `/responsive-320.html`. الحسابات الوهمية متاحة من `/review-credentials` محليًا فقط، وكلمات مرورها عشوائية في الذاكرة ولا تحفظ في المشروع. لتشغيل المعاينة استخدم `node scripts/run-emulator.mjs --preview`؛ أضف `--slow` فقط لإعادة جولة التأخير الشبكي. يتطلب الاختبار Firebase CLI وJava المثبتين محليًا.
